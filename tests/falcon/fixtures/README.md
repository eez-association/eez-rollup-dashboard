# Public Falcon test fixtures

These fixtures contain public inputs and runtime bytecode only. Test-generated
private keys are ephemeral and are never committed.

- `nist-kat.json`: cases 0–9 from ETHFALCON commit
  [`820da4b6f66c1ada61b6429b80da10fad0d4efc6`](https://github.com/ZKNoxHQ/ETHFALCON/blob/820da4b6f66c1ada61b6429b80da10fad0d4efc6/test/falcon512-KAT.rsp).
  The source SHA-256 is `dd75c946fdedef4ec46a2bee7e10c65c9126f1a839b9ced6921fd45f7354b5cd`.
  The attached format `length[2] || nonce[40] || message || 0x29 || s2` was
  converted to `0x39 || nonce[40] || s2 || zero padding` (666 bytes), checking
  message/lengths without changing coefficients or nonce. Only messages,
  public keys and signatures are retained. These are independent of noble.
- `browser.json`: frozen public message/signature/key generated by the POC in
  Chromium 153 with noble 0.7.1 and accepted by its local Solidity verifier.
- `safe-costs.json`: public signed transaction/receipt fixture imported from the
  POC for independent calldata/blob and accounting regressions. See the
  [model provenance](../../../docs/falcon/cost-comparison.md).
- `deployed-code.json`: public `eth_getCode` responses captured 2026-10-30 from
  EEZ-X 916969 and Chiado 10200 through their configured read RPCs.
  Every address/runtime hash is checked against
  the feature deployment bindings before using the fixture. These let wallet
  tests retain bytecode checks without making external RPC requests. They do
  not execute an EVM; RPC, receipts and cross-chain transport remain mocks.
- `testnet-deployed-code.json`: verifier and controller factory runtime code
  captured after deployment and full explorer verification on eez.dev chain
  699169 on 2026-10-30. Chiado Safe contracts are shared with the original
  deployment. Both networks' wallet scenarios check their respective code hashes.

The verifier uses ETHFALCON's pinned SHAKE256 implementation under the included
[MIT license](ETHFALCON-LICENSE.txt), wrapped by the demo's strict padded-format
verifier. Its verified sources are available at the
[EEZ-X explorer](https://eez.asuscomm.com/explorer/address/0x1F7B6E9BfC86F2d72C44E3cEF9b133C59c57C6E9).
SafeL2 and CompatibilityFallbackHandler bytecode comes from Safe's unmodified
1.4.1 release at
[`bf943f80fec5ac647159d26161446ac5d716a294`](https://github.com/safe-global/safe-smart-account/tree/bf943f80fec5ac647159d26161446ac5d716a294),
under the included [LGPL-3.0 license](SAFE-LICENSE). SafeL2's name refers to its
event-emitting implementation, not the chain on which the demo places the Safe.
